# ResearchPilot

ResearchPilot 是一个开源技术研究工作台，用于查阅官方文档、理解开源实现和比较技术方案。输入研究问题后，工作台在后台整理计划、采集并归档证据，生成可逐条核对引用的报告。

[打开线上工作台](https://researchpilot.towerman1990.cn) · [下载 Windows x64 安装包](https://github.com/towerman1990/researchpilot/releases/tag/v0.1.2) · [技术文档](docs/README.md)

## 技术要点

| 技术 | 在项目中的应用 |
| --- | --- |
| Go、Hertz、React、Vite、Ant Design | 提供研究 API、浏览器工作台与 SSE 实时进度。 |
| Eino 与多 Agent 分工 | 编排规划、取证、证据分析、报告撰写与引用复核。 |
| RAG 与混合检索 | 检索公开摘要或私有文档并归档证据；默认关键词检索，可配置嵌入服务启用余弦相似度与 RRF，Milvus 为可选后端。 |
| MCP、Brave Search 与 GitHub | 发现官方资料、读取网页和固定提交的源码；提供只读 MCP 客户端与服务端。 |
| MySQL、Redis、Asynq | 通过事务 Outbox、租约、执行代次与检查点支持异步派发、重试和断点续跑。 |
| 会话与上下文管理 | 在会话内组织多轮独立研究，携带首轮及近期报告摘录，并与用户保存的长期研究记忆共同使用。 |

## 开始研究

1. 打开工作台即可输入具体的技术问题。访客每天可提交 5 次研究（北京时间零点重置），第 6 次提交时可在弹窗中登录或注册。可以附上公开网页、GitHub 链接或研究资料。
2. 提交后即可查看实时进度。需要控制取证范围时，可以先审阅和修改计划，再确认开始。
3. 报告生成后，打开「核查证据」阅读支持关键结论的摘录，也可以下载 Markdown、通过打印窗口另存为 PDF。在会话底部继续提问，可逐轮查看问题、进度和报告；换一个主题时点击「新建会话」。

线上平台模型为每个账号提供**累计 10 次免费试用**，额度不按天重置。任务创建成功时扣减一次，同一任务的重试或恢复不会重复扣减，失败或取消不返还。用完后，可在「模型设置」配置自己的 OpenAI 兼容接口，包括 Base URL、模型名称和 API Key。使用个人模型不消耗试用次数。可以保存多套配置，切换后对新任务生效。

Windows x64 客户端采用 MyGo 和 WebView2，默认连接线上工作台，与网页版共享账号、任务和报告。GitHub 上的 `v0.1.2` 是未签名预发行版，发布页提供安装包和 SHA-256 校验文件。[Windows 安装与升级说明](docs/13-M3-DESKTOP.md)

## 主要功能

| 功能 | 使用方式 |
| --- | --- |
| 证据采集 | 读取公网页面、公开 GitHub 仓库及固定提交的源码，支持定向分析仓库目录和依赖清单。提交时还可上传最多两份 UTF-8 的 TXT 或 Markdown，每份不超过 24 KiB。 |
| 会话与多轮研究 | 同一会话承载多轮研究，支持加载更早轮次、刷新后恢复当前研究，以及确认后删除会话。 |
| 报告与反馈 | 查看归档摘录、导出报告、提交反馈，或在当前会话继续追问。启用「发布前复核引用」后，模型会检查结论与摘录是否相符。 |
| 任务管理 | 在多任务工作区集中查看运行中、待审批和已结束的任务。研究中可以查看实时进度、取消任务，或重新打开历史任务。 |
| 定时研究 | 使用个人模型创建单次、每天或每周运行的计划，可在站内订阅结果。每天和每周按固定 24 小时和 168 小时间隔触发。 |
| 研究偏好与评估 | 保存来源、详略和报告结构偏好，查看近 7 天或 30 天的研究结果、反馈和模型用量，并按个人模型价格估算费用。 |
| 使用统计 | 工作台底部以小字显示今日及累计研究使用人数、次数；登录按账号、访客按 IP 去重。 |

研究材料不足时，工作台会尝试生成并复核有依据的部分结论，同时说明证据缺口。无法形成可信结论或预算不足时，保留已归档摘录作为「部分完成」报告。配置模型后，与任务相关的上传资料摘录会发送给该任务使用的模型服务。

### 检索评估与恢复演示

「研究评估」内可查看内置检索对照，也可导入评估命令生成的 JSON，对比策略指标、漏召回和无答案误命中。任务运行记录会标出恢复后复用了哪些检查点。 [复现步骤](docs/15-KNOWLEDGE-MCP.md)

### GitHub 仓库分析

在研究目标中给出公开 GitHub 仓库和想了解的目录或模块。目录与依赖证据固定到同一提交。Go 和 JavaScript 清单会提取声明的依赖约束、Go 工作区成员、本地替换或 JavaScript workspace 依赖。npm 的 package-lock.json（格式 2 或 3，最大 1 MiB）可核对根项目直接依赖的版本约束和锁定版本，并展示部分传递依赖的引入链及其锁文件路径。锁文件记录的仓库内工作区链接也可展开，从链接目标目录解析依赖。锁文件摘要会优先展示研究问题中点名的包。查看实现行为时，报告可引用同一提交的源码文件。

### 会话与连续研究

侧边栏按会话组织历史。「新建会话」提交首个问题，后续问题在会话底部继续输入。例如先问「比较两种 Go 服务部署方案」，再问「如果服务器只有 2 GiB 内存，该怎样调整？」两轮研究会归在同一会话中，每轮保留自己的进度、引用和报告，可在同一页面查看并加载更早的对话。刷新页面会恢复当前研究，历史独立任务和原有追问链也已归组。

当前轮结束后才能继续提交，失败或取消后也可在原会话发起新的研究。新轮次会参考首个问题和最近几轮的问题、报告摘录，背景内容仍需用本轮归档证据核实。每轮独立使用 Token 预算，并按一次新研究计入试用额度和站点统计。会话历史用于延续当前主题；长期研究记忆由用户主动保存，用于给后续不同会话提供背景。

会话旁的删除按钮需确认后生效。删除当前会话会返回新建页面，并取消尚未完成的研究。采用软删除，历史列表隐藏该会话，报告仍保留在数据库中，同身份的原有任务和报告直链接口仍可访问。目前没有恢复或彻底清除入口，删除也不会清空长期记忆或扣减已有使用统计。

### 使用人数与次数

工作台底部显示今日和累计的研究使用人数、次数。成功提交研究和追问计次，同一请求的幂等重放、任务重试和恢复不会重复计次。登录按账号、访客按 IP 去重，每日按北京时间划分。统计从功能启用后开始，可见页面约每分钟刷新；这些数字反映研究使用情况，多个访客共用出口 IP 时会合并统计。

### 多 Agent 分工

发起研究时勾选「启用多 Agent 分工」。规划和资料采集完成后，证据分析员整理带来源 ID 的交接笔记，撰稿员结合归档原文写报告，引用审核员在发布前核对结论。运行记录显示角色和检查点。各角色共享该任务的模型配置和 Token 预算，启用后会增加模型调用。

### 长期研究记忆

登录后，在「研究偏好」填写并保存长期研究记忆。新研究、追问和定时研究生成报告时会参考这段背景，当前目标的具体要求优先。清空后保存只影响之后创建的任务，已创建的任务继续使用提交时的快照。

### 历史报告对比

在报告中点「对比报告」，从研究历史选择基准报告。对比会列出当前新增、仅在基准报告出现的结论，以及正文相同但引用列表有变化的结论。可打开基准报告核对归档证据。文字改写也可能形成差异，适合与同一目标的上次定时研究对照使用。

### 私有知识库

登录后可在「私有知识库」建库并导入不超过 24 KiB 的 UTF-8 Markdown 或 TXT。后台索引完成后，在新建研究时选用资料库。同名导入会创建新版本，研究时使用最新已索引版本，旧报告仍可回查任务归档的原有段落。 [私有知识库说明](docs/15-KNOWLEDGE-MCP.md#私有知识库)

### 公开知识库与 MCP 演示

在新建研究时勾选「先查公开知识库」，可使用内置的 .NET、ASP.NET Core 和 Go 资料摘要。试试「HttpClient 如何在复用连接池的同时应对 DNS 记录变化？」命中的摘要会作为任务证据归档，报告可回查摘要版本和官方出处。资料不足时，任务继续查找外部来源，包括已启用的 Microsoft Learn MCP。

默认使用关键词检索。可为 Worker 配置 OpenAI 兼容的嵌入端点以启用混合检索，也可在本地启动只读 MCP 服务，让外部客户端搜索同一公开资料库。配置和演示步骤见 [知识库与 MCP](docs/15-KNOWLEDGE-MCP.md)。

### 搜索与文档工具

未配置网页搜索时，模型可以规划公开来源，显式提供 URL 有助于限定资料范围。自托管时可通过 `BRAVE_SEARCH_API_KEY` 启用 Brave 搜索。搜索结果用于定位资料，报告引用以实际读取并归档的原文为依据。

自托管时设置 `MICROSOFT_LEARN_MCP_ENABLED=true`，可启用 Microsoft Learn 的四个预设主题，覆盖 ASP.NET Core Minimal API 路由、.NET HttpClient、Azure App Service 自定义容器和 WSL 容器。真实 Brave 调用仍待项目验收。

## Docker Compose 本地运行

从仓库根目录执行。Windows 需要 PowerShell 7 和可用的 Docker Compose。

```powershell
pwsh -File ./scripts/init-local.ps1
docker compose up --build -d
docker compose ps -a
```

macOS 和 Linux 可使用 Shell 初始化。

```sh
sh scripts/init-local.sh
docker compose up --build -d
docker compose ps -a
```

`migrate` 服务退出码为 0 后，API 和 Worker 会启动。打开 [本地工作台](http://localhost:8080) 即可试用。登录后可在「模型设置」配置个人模型，运行真实研究。默认本地配置在没有个人模型或平台试用时运行演示任务。

升级前备份数据库，并保留初始化生成的 `.cache/model-master.key`，恢复加密的模型配置时需要原密钥。[macOS / Linux 部署指南](docs/14-MACOS-LINUX.md) · [生产部署与恢复指南](docs/12-M3-RELEASE.md)

## 架构与排查

后端使用 Go 和 Hertz，前端使用 React、Vite 和 Ant Design。会话负责组织连续问题，各轮仍是独立研究任务。API 在事务内锁定会话并分配轮次，将任务和待派发记录一并写入 MySQL；Worker 通过 Redis 和 Asynq 领取任务，使用 Eino 编排「计划 → 取证 → 覆盖检查 → 必要时重规划 → 合成报告」。租约和检查点支持中途恢复。浏览器通过 SSE 接收进度，断线后可按 `Last-Event-ID` 续传。

程序入口位于 `cmd/researchpilot`。`internal/wiring` 负责依赖装配，`internal/handler` 提供 HTTP 接口，`internal/task` 和 `internal/execution` 分别负责任务管理和研究执行，`internal/repository` 管理 GORM Gen 查询和事务。

新任务详情可复制「创建请求 Log ID」。生产日志保留同一个任务创建编号，便于关联 API、Worker 和执行步骤。

```powershell
docker compose logs api worker | Select-String -SimpleMatch '<Log ID>'
```

## 开发与验证

源码构建需要 Go 1.25+、Node.js 22.12+ 和 npm。可运行 `go test ./...`、`go vet ./...` 及 `npm --prefix web ci`、`npm --prefix web run build`。本地启动后可使用 `pwsh -File ./scripts/smoke.ps1` 检查演示闭环。

GitHub CI 包含 Go/MySQL、前端、开发 Compose 和生产 Compose 四组检查。独立的镜像发布工作流要求对应提交的 CI 成功，再将 `linux/amd64` 镜像发布至 GHCR。[CI 工作流](.github/workflows/ci.yml) · [镜像发布工作流](.github/workflows/release-image.yml)

最新一轮隔离环境评估使用 DeepSeek，十道固定技术题均未提供 URL。在未启用 Brave 的情况下，10 道题生成完整报告，全部通过归档引用完整性检查。该结果仅代表本轮固定题集的自动结果。[评估记录与复现方法](docs/11-M2-EVALUATION.md)
