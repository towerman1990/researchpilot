## 诊断与修复过程

没有把第一轮自动“成功”直接当作质量通过。初轮有报告缺少请求头 / 空闲 / 关闭相关的关键字段，却被任务状态标为完成；后续增加了依据归档证据的 Observe 检查，缺口无法补齐时明确返回 PARTIAL。

复测发现并修复：

1. Fake-IP 使模型域名落入保留地址，新增可选可信 HTTPS DNS，保持 TLS、全部返回地址校验与实际连接固定。
2. 长文档只截开头、导航干扰、未加引号的 HTML 锚点未被识别。
3. 多个相同 URL 的片段挤掉互补章节；改为每 URL 保留一份输入，并优先保证主文档额度。
4. 覆盖 JSON 引号未转义却被当作资料不足；新增一次有界格式修正，失败仍不放行。
5. GitHub 未认证 API 配额耗尽。已确认 remaining=0；降级时只从公开页面嵌入状态读取当前提交，再读取该 SHA 的公开 README，不使用任意 README 文本猜提交，也不把 API 凭据转发给公开页面或 CDN。

诊断轮、失败轮与单题复测留在本机忽略目录。最终 8/10 取自同一整组运行，不拼接不同批次的单题成功结果，也没有替换题目或降低门槛。
