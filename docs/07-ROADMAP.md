# 工程计划与验收

## 交付顺序

| 阶段 | 可验收产物 |
|---|---|
| M0 设计与试验 | 确认 ADR、HTTP SSE 对照、桌面壳样包，固定供应商兼容性基线。 |
| M1 最小闭环 | Compose、账号认证、任务创建、Provider 与工具桩、Web 显示事件。 |
| M2 研究与恢复 | 三工具、证据校验、报告、租约、补偿投递、取消重试与故障注入。 |
| M3 双端与发布 | Windows 安装包、双端共享账号与任务、验收样本、部署备份和回滚手册。 |
| P1 / P2 | 按 PRD 拓展，先补评估和用户反馈，再推进长期记忆、深度分析与多 Agent。 |

## MVP 验收

| 编号 | 可重复验证的条件 |
|---|---|
| A1 | 新用户创建任务并看到计划、工具结果及引用报告。用 10 个固定技术题做评估，建议至少 8 个交付可用报告，抽查主要断言与证据一致，Source ID 有效且无模型杜撰链接。 |
| A2 | 同租户相同键与相同 payload 只在库内创建一条任务；更换 payload 得 409。模拟重复交付、入队前后宕机、Worker 中断和 Redis 队列丢失，检查点可恢复且只有一份已发布终态报告。 |
| A3 | 剪断网络并确保 SSE 回放无缺项，客户端去重。用 100 条长连经代理验证，建议已提交事件到前端 p95 在 2 秒内；游标过期触发快照恢复。 |
| A4 | 取消、达到 deadline 和预算耗尽均进入可解释的合法状态。建议受理取消后 10 秒内收口；过期 epoch 的 Worker 无法提交。 |
| A5 | 用隔离测试夹具验证出站策略、恶意网页内容只作为数据、跨租户访问被拒、密钥轮转有效且日志与 SSE 无明文。 |
| A6 | Web 与 Windows 安装包登录同一账号并复用历史任务、报告、导出与重连接口；从新机器按文档启动 Compose 和执行恢复演练。 |

## 可观测性与测试

以 OpenTelemetry 串联 API、outbox、Worker、模型和工具，结构化日志含 trace_id、task_id、phase、attempt、错误码及耗时。指标涵盖队列等待和深度、最老 outbox、执行时长、失败率、重试、租约回收、Token、引用覆盖、SSE 连接与回放延迟。指标标签保持低基数。仪表盘可区分服务故障、供应商限流与任务预算耗尽。初版告警建议包含待派发时间、失败突增与积压，阈值经压测确定。

CI 跑 Go 单元与 race、前端单测、模型/工具契约、MySQL/Redis 集成、Web 端到端和 Windows 安装烟测。模型用可重复桩覆盖畸形参数、部分流、超时与重规划，真实模型评估独立运行。用故障注入覆盖提交前后、重复投递、取消与完成竞争、数据库恢复及断线重放。

## 部署与回滚

Compose 固定依赖版本并配健康检查，反代终止 TLS，数据库和 Redis 使用内部网络及持久卷。发布先备份 MySQL，再运行向后兼容迁移，先令 Worker 停止领新任务并排空，再替换应用实例；用迁移兼容窗口支持镜像回退。异地演练备份恢复，恢复后对账待处理任务并重建队列。由环境变量注入密钥引用，密钥保存在受限设施中。初始留存建议：事件 30 天，报告和证据由用户删除或按部署策略回收；完成验证前作为提案。
